## 修正内容

- `GenerationBudget` で生成時間と中断状態を共有する。並行した承認待ちも参照数で管理し、全承認待ちが終了するまで生成時間を再開しない。終了時には残る待機と遅いツール通知も中断する。
- 承認要求はサーバーで接続ごとに直列化する。待機中の要求は承認できず、表示中の要求だけを承認できる。切断時には表示中・待機中とも拒否し、手動切断でも画面の確認を閉じる。
- 履歴の取得・削除エラーは画面内で表示する。取得は再試行でき、マスコット切り替え前の遅い通信結果を適用しない。
- 送信開始時のメッセージ配列と会話を保持し、表示先が変わっても応答・失敗状態を元の会話へ反映する。
- 通常会話の選択IDを接続先・利用者・マスコットごとに保存する。本文やシークレット会話はローカルへ複製しない。会話タイトル生成を共通化する。
- コンテキスト長超過を入れ子のエラーから判定し、認証情報を含まない固定の案内を返す。
- LM Studio管理APIを `message` 形式へ統一し、`URL.canParse` への依存を除去した。READMEのNode.js要件は実際のMastra依存要件である22.13.0以上へ更新する。
- LoRA一覧取得を専用処理へ分離し、HTTP/HTTPS以外を拒否、成功・失敗ともタイマーを解除、固定の失敗形式を返す。
- 全体仕様書とMastra仕様書を更新する。

## 改善提案・検証事項

- 添付のBase64保存と全会話の一括取得は実装上の事実。容量増加時のページ分割・添付の別保存はデータ形式とAPI設計を伴うため、今回の回帰修正とは分けて管理する。既存データを切り捨てる制限は追加しない。
- 最終依存構成での本番ビルド・配布版起動は検証事項。PR本文から「最終更新後の配布版再作成・画面確認が未実施」と分かるが、`npm run build` 自体の未実施までは断定しない。
- 通常チャットはMastra Memoryを正本とし、初期挨拶は画面表示用とする。シークレット会話は保存しない。

## 元レビューの訂正

- LoRA一覧取得が「500例外へ落ちる」は不正確。外側の `catch` が失敗結果を返している。修正対象はタイマー・入力検証・失敗形式である。
- Androidのファイル選択が画像専用であることは `docs/specs/Android.md` に記載済み。仕様変更は行わない。
- `RequestContext` はモデルオブジェクトを保持する。モデル内部に認証情報が存在し得るため、「認証情報を一切保持しない」ではなく「スパン・通常ログ・クライアント応答へ展開しない」と評価する。
- 60秒制限自体は現行仕様。R5は承認UIを含む運用上の改善として仕様と合わせて変更する。
