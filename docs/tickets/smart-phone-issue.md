# スマートフォンWeb版 移植設計・仕様書 (SmartPhoneWeb.md)

本ドキュメントは、現在 Electron + Nuxt 3 (Vue 3) + TypeScript で構築されている `tonarice` アプリケーションを、iOS Safari および Android Chrome などのスマートフォンWebブラウザ上で動作可能にするための設計・仕様を定義します。

まずはネイティブアプリ化（Capacitor等）を行わず、スマホブラウザ上で快適に動作するWebアプリとしての実装を第一目標とします。

---

## 1. スマホブラウザ特有の課題と対策

スマホブラウザでの動作において、デスクトップ版や単純なWebアプリと異なる以下の課題に対処します。

### 1.1. ソフトウェアキーボード（IME）表示時のレイアウト崩れ対策
チャットのテキスト入力時にソフトウェアキーボードが表示されると、画面の下半分が隠れ、レイアウトが崩れたり入力欄が見えなくなったりする問題が発生します。

* **対策**:
    * **`visualViewport` API の活用**:
      `window.visualViewport` を監視し、キーボード表示によるビューポートの高さ変化（`height`）および位置変化（`offsetTop`）を動的に検知します。
    * **入力欄の追従**:
      キーボードが表示された際、入力フォーム領域（チャット入力欄）の位置を `visualViewport` の下端に吸い付くように CSS または JS で動的に調整（位置を固定）します。
    * **チャット履歴のスクロール位置保持**:
      ビューポートが縮小した際、チャット履歴の最新メッセージが見える位置まで自動でスクロールする制御を入れます。
    * **viewport-fit の指定**:
      HTML のメタタグで `viewport-fit=cover` を指定し、全画面での表示領域を適切に確保します。

### 1.2. 画面上部ステータスバー（Status Line）およびノッチ（Safe Area）の回避
スマートフォンのノッチ（切り欠き）や画面上部のステータスバー、パンチホールカメラ、下部のホームインジケーター（iOS）と、アプリのUI（ヘッダーや操作ボタン）が被らないようにする必要があります。

* **対策**:
    * **CSS 環境変数の利用**:
      `env(safe-area-inset-top)`、`env(safe-area-inset-bottom)` などの CSS 環境変数をパディングやマージンに適用します。
      ```css
      .header-container {
          padding-top: env(safe-area-inset-top, 20px);
      }
      .input-container {
          padding-bottom: env(safe-area-inset-bottom, 16px);
      }
      ```
    * **Web App Manifest でのテーマカラー指定**:
      `manifest.webmanifest` の `theme_color` および `background_color` を適切に設定し、OSのステータスバー領域の色がアプリのテーマ（ダークモード等）と調和するようにします。

### 1.3. 100vh問題の解決（アドレスバー開閉への対応）
スマホブラウザで `height: 100vh` を使用すると、アドレスバーやナビゲーションバーの高さが含まれてしまい、コンテンツの下部が画面外にはみ出す問題があります。

* **対策**:
    * **CSSの `dvh`（Dynamic Viewport Height）の採用**:
      アドレスバーの開閉に合わせて高さが動的に変化する `100dvh` を使用して、画面全体の高さを定義します。これにより、アドレスバーが出ている状態でもコンテンツが見切れるのを防ぎます。
      ```css
      .app-layout {
          height: 100dvh;
          display: flex;
          flex-direction: column;
      }
      ```

### 1.4. 音声再生の制約回避（Autoplay Policy）
モバイルブラウザでは、ユーザーの明示的なインタラクション（タップ等の操作）がない限り、プログラムから自動で音声を再生（Style-Bert-VITS2 等による音声合成の再生）することがブラウザのセキュリティポリシーで禁止されています。

* **対策**:
    * **初回タップによる解放**:
      アプリ起動時に「マスコットと対話を開始」のようなスタート画面または初期タップを求めるUIを表示し、ユーザーの初回のインタラクションで Web Audio API の `AudioContext` を解放（Resume）します。これ以降は、中継サーバーから返ってきた音声合成データを自動で再生できるようにします。

### 1.5. ストレージの永続性とデータ容量
ブラウザの LocalStorage や IndexedDB は、OSの空き容量が急に減った際や長期間アプリを起動しなかった際、ブラウザによって自動的に削除されるリスク（Eviction）があります。

* **対策**:
    * **データの役割分担**:
      * アプリの基本設定やチャット履歴: ブラウザの IndexedDB に保存します。
      * マスコット画像・アセット: スマホ端末側でカスタムマスコットを追加する場合、画像データは Base64 等に変換して IndexedDB に保存しますが、容量制限を考慮し、デフォルトマスコットはサーバーから配信（URL参照）する形式を主とします。
    * **中継APIサーバーへのデータ保存（オプション）**:
      重要な設定や履歴は、可能であれば中継APIサーバー側にアカウントやセッション単位で永続化する仕組みへの拡張を検討します。

## 2. 画面レイアウト・UI設計

スマートフォンの縦長画面（ポートレート）および横長画面（ランドスケープ）に最適化したレスポンシブデザインを定義します。

### 2.1. 縦画面（スマートフォン標準）の構成
スマートフォンの縦持ちでは、画面を上下に分割したレイアウトを採用します。

* **上部：マスコット表示エリア**
    * 背景は透過ではなく、設定されたテーマカラー、グラデーション、または背景画像を表示。
    * マスコットのアニメーション（Spine や Live2D、GIF等）を表示。
    * マスコットからの吹き出し（セリフ）はマスコットの近くにオーバーレイ表示。
* **下部：チャット履歴＆入力エリア**
    * スワイプ操作で上下に伸縮、または折りたたみ（最小化）ができる設計。
    * チャット履歴を縦スクロールで閲覧可能。
    * テキスト入力フォームは最下部に固定（キーボード表示時はキーボード上部に吸着）。

```
+-----------------------------------+
| [Gear Icon]         [Status Line] |
+-----------------------------------+
|                                   |
|             Mascot                |
|            (Animation)            |
|                                   |
|        +-------------------+      |
|        | 吹き出しセリフ    |      |
|        +-------------------+      |
+-----------------------------------+
| === チャット履歴・入力エリア ===== |
| - User: こんにちは                |
| - Mascot: こんにちは！            |
|                                   |
| [ テキストを入力...         ] [送信] |
+-----------------------------------+
```

### 2.2. 横画面（タブレット・スマホ横持ち）の構成
画面を左右に分割したレイアウトを採用します。

* **左側：マスコット表示エリア**
* **右側：チャット履歴＆入力エリア**

## 3. PWA (Progressive Web App) 対応

スマホのWebブラウザから「ホーム画面に追加」することで、ネイティブアプリのように起動できるようにします。

* **マニフェストファイル (`manifest.webmanifest`)**:
    * `display: standalone` に設定し、ブラウザのアドレスバーやナビゲーションバーを非表示にし、ネイティブアプリ同様の全画面表示を実現します。
    * `orientation: portrait` または `any` を設定。
* **iOS Web App Capable メタタグ**:
    * iOS Safari 向けに以下のタグを設定します。
      ```html
      <meta name="apple-mobile-web-app-capable" content="yes">
      <meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
      ```
* **サービスワーカー (Service Worker)**:
    * 静的アセット（JS、CSS、デフォルトマスコット画像）をキャッシュし、起動速度の向上とオフラインでの部分動作を実現します。

## 4. 実装・検証ロードマップ

### フェーズ 1: スマホ向けレスポンシブレイアウトの実装
1. メディアクエリ（Tailwind CSS等）を用いた、スマホ縦画面用の上下分割レイアウトの実装。
2. 背景画像の指定機能、および吹き出しのモバイル向け最適化。
3. `100dvh` および `safe-area-inset-*` を用いたノッチ・ステータスバー・ホームバー回避の実装。

### フェーズ 2: ソフトウェアキーボードと音声再生の対応
1. `visualViewport` API を用いた、キーボード起動時のレイアウト制御スクリプトの実装。
2. 初回タップによる AudioContext のアクティベーションと、Style-Bert-VITS2 音声再生の動作検証。
3. スマホの実機デバッグ（iOS Safari / Android Chrome）による表示・入力操作の検証。

### フェーズ 3: PWA対応と永続化
1. PWA マニフェストファイルの作成、アプリアイコンの設定。
2. サービスワーカーの導入と、ローカルストレージ（IndexedDB）へのデータ永続化の実装。
3. インターネット経由の中継APIサーバー（HTTPS）との接続テスト。
