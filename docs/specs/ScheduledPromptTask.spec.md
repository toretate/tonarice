# 定期実行タスク・CoWork モード仕様書

> ステータス: ベース仕様（実装前）
>
> 本書は、指定したプロンプトを定期的に実行し、その結果を専用の会話領域へ報告する機能の初期仕様を定める。

## 1. 目的

- ユーザーがプロンプトと実行周期を登録できる。
- アプリ起動中、登録した周期で AI へプロンプトを送信する。
- 実行結果を通常会話と混在させず、`CoWork` のチャットへ報告する。
- 現在のチャットヘッダーから `Chat` と `CoWork` を切り替えられる。
- 実行成否、次回実行日時、直近の結果をユーザーが確認できる。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 会話種別 | `Chat` または `CoWork`。表示するメッセージ履歴と利用目的を分ける単位。 |
| Chat | ユーザーとマスコットが通常の会話を行う既存の会話種別。 |
| CoWork | 定期実行タスクの登録、実行結果の確認、結果に対する追加会話を行う会話種別。 |
| 定期実行タスク | プロンプト、実行周期、実行状態を持ち、指定時刻に AI 実行を要求するジョブ。 |
| 実行結果 | 定期実行タスクごとの AI 応答、エラー、開始・終了日時を含む記録。 |

## 3. 既存機能との境界

### 3.1. タスク管理ウィジェットとの違い

`docs/specs/widgets/task-management/` のタスクは、ユーザーの予定や TODO を管理・通知する機能である。本機能は AI にプロンプトを実行させる機能であり、データモデルと実行基盤を分離する。

- タスク管理の `Task`、`scheduledAt`、`recurrence` は流用しない。
- 定期実行タスクから通常の TODO を作成する場合は、将来の連携機能として扱う。
- 「予定を知らせるだけ」は既存タスク管理またはタイマー、「調査・要約等を AI に実行させる」は本機能を使用する。

### 3.2. 既存チャットモードとの関係

`Chat / CoWork` は会話種別であり、次の既存状態とは独立する。

- シークレットモード
- ラジオモード
- 画像生成モード
- ウィンドウモード（分割、統合、コンパクト）

初期リリースでは CoWork からラジオモードと画像生成モードを開始できない。シークレットモードは Chat のみに適用し、CoWork の定期実行結果は永続保存する。

## 4. 対象範囲

### 4.1. 初期リリースに含む

- `Chat / CoWork` の切り替え UI。
- CoWork 専用の履歴。
- 定期実行タスクの一覧、作成、編集、有効化、無効化、削除。
- タスクの即時実行。
- 毎時、毎日、毎週、指定間隔の実行周期。
- 実行結果とエラーの CoWork 履歴への投稿。
- 次回実行日時、最終実行日時、最終結果の状態表示。
- アプリ再起動後のタスク復元。
- アプリ終了中に実行時刻を過ぎたタスクの補完実行。
- 同一タスクの多重実行防止。

### 4.2. 初期リリースに含まない

- アプリが終了している間のバックグラウンド実行。
- OS のタスクスケジューラへの登録。
- 複数端末間の同期。
- 外部チャット、メール等への投稿。
- 任意の cron 文字列入力。
- タイムゾーンをまたぐ高度な RFC 5545 対応。
- 失敗時の自動リトライ。
- タスク間の依存関係やワークフロー。

## 5. ユーザー体験

### 5.1. 会話種別の切り替え

現在のチャットヘッダーに表示している「`マスコット名 Chat`」を、ネイティブなドロップダウンリストへ置き換える。

- 選択肢は `Chat` と `CoWork`。
- 初期値は `Chat`。
- 表示例は `マスコット名 / Chat`、`マスコット名 / CoWork` とする。
- 選択変更時にページ遷移や新規ウィンドウを開かず、同じチャット領域の内容を切り替える。
- 選択中の会話種別はウィンドウ間で同期し、アプリ再起動後も復元する。
- キーボードでフォーカス、選択、確定でき、明示的なラベルを持つ。
- ヘッダーのドラッグ操作はドロップダウン上で開始しない。

### 5.2. CoWork のワークスペース

CoWork は定期実行だけに限定せず、今後さまざまな作業機能を追加できるワークスペースとする。

- 広い表示領域では、左に機能メニュー、右に選択した機能の内容を表示する。
- 左メニューの初期項目は `概要` と `スケジュール` とする。
- `概要` には利用できる作業機能への導線と、最近の実行結果を表示する。
- `スケジュール` には定期実行タスクの作成、一覧、状態、実行結果を表示する。
- タスク作成ボタンは左メニューとスケジュール画面のヘッダーから利用できる。
- メニュー項目を増やしても右側の表示領域を共用できる構造とする。
- チャット領域の横幅が狭い場合は左メニューをアイコンだけの細いレールへ畳み、マウスオーバーまたはキーボードフォーカス時に内容の上へオーバーレイ表示する。
- 狭幅判定にはアプリまたは統合ウィンドウ全体ではなく、CoWork が配置されているチャット領域の実幅を使用する。
- DOM とキーボードフォーカスは、メニュー、選択中の内容の順とする。

将来追加する CoWork の追加入力と会話履歴は、選択中の作業機能を妨げない位置へ配置する。タスク作成・編集フォームはスケジュールの内容領域に表示し、閉じると同じ一覧へ戻る。

### 5.3. 定期実行タスクの入力項目

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 名前 | 必須 | 一覧と実行結果に表示する短い名称。1〜100文字。 |
| プロンプト | 必須 | AI へ送信する内容。1〜20,000文字。 |
| 周期種別 | 必須 | `interval`、`hourly`、`daily`、`weekly`。 |
| 間隔 | 条件付き | `interval` は15分以上、他は1以上の整数。 |
| 時刻 | 条件付き | `daily`、`weekly` で指定するローカル時刻。 |
| 曜日 | 条件付き | `weekly` で1つ以上選択する。 |
| 有効 | 必須 | 保存直後からスケジュール対象にするか。既定は有効。 |

フォームは常に可視ラベルを持つ。エラーは対象項目と関連付け、入力後に表示し、保存失敗は `aria-live="polite"` 相当の通知領域でも伝える。

### 5.4. タスク一覧

各タスクに次を表示する。

- 名前。
- 周期の読みやすい要約。
- 有効・無効。
- 次回実行日時。
- 最終実行日時と `成功 / 失敗 / 実行中`。
- `今すぐ実行`、`編集`、`有効化 / 無効化`、`削除`。

削除は確認後に実行する。実行履歴はタスク削除時にも残し、投稿内のタスク名を表示できることとする。

### 5.5. CoWork への投稿

1回の実行につき、完了後に1件の結果メッセージを追加する。

- タスク名。
- 予定実行日時。
- 実際の開始・終了日時。
- 成功時は AI 応答本文。
- 失敗時はユーザー向けの簡潔なエラー。
- 手動実行か定期実行か。

結果追加時、ユーザーが CoWork を表示中なら通常の新着メッセージとして表示する。Chat 表示中なら会話を自動切り替えず、CoWork 選択肢に未読状態と件数を表示する。新着通知は標準優先度で通知し、読み上げを割り込ませない。

## 6. スケジュール仕様

### 6.1. 時刻とタイムゾーン

- タスクは作成時の IANA タイムゾーンを保持する。初期値は OS の現在タイムゾーン。
- 次回実行日時は ISO 8601 形式で保持する。
- 日次・週次は現地時刻を優先し、夏時間による時刻変更後も指定した壁時計時刻を維持する。
- OS のタイムゾーン変更後は、保存済みタイムゾーンを維持し、自動変更しない。

### 6.2. 起動中の発火

- Electron メインプロセスをスケジュール判定の単一所有者とする。
- 次回実行日時に達した有効タスクを実行キューへ追加する。
- 同一タスクは同時に1回だけ実行できる。
- 前回実行中に次の時刻へ達した場合、その回は重ねて起動せず `skipped` として記録する。
- タスク間は初期リリースでは直列実行とし、AI API への同時負荷を抑える。

### 6.3. アプリ終了中の取りこぼし

アプリ終了中は実行しない。次回起動時、最終判定日時から現在までに1回以上の予定があるタスクは、最新の1回だけ補完実行する。

- 過去の全回を連続実行しない。
- 補完実行は通常の定期実行として投稿し、予定実行日時を併記する。
- 無効なタスクは補完しない。
- 7日より古い取りこぼしは実行せず、`skipped` として記録する。

### 6.4. 失敗時

- AI 接続、認証、タイムアウト等の失敗を実行履歴と CoWork に記録する。
- 初期リリースでは自動リトライしない。
- 失敗しても次回予定は通常どおり計算する。
- 外部通信のログは既存の実装ルールに従い、秘密情報とプロンプト全文を平文ログへ出さない。

## 7. データモデル

```ts
type ConversationKind = 'chat' | 'cowork';

type ScheduleRule =
    | { type: 'interval'; intervalMinutes: number }
    | { type: 'hourly'; intervalHours: number; minute: number }
    | { type: 'daily'; intervalDays: number; time: string }
    | { type: 'weekly'; intervalWeeks: number; weekdays: number[]; time: string };

interface ScheduledPromptTask {
    id: string;
    name: string;
    prompt: string;
    schedule: ScheduleRule;
    timeZone: string;
    enabled: boolean;
    nextRunAt: string;
    lastRunAt?: string;
    lastStatus?: 'success' | 'failed' | 'skipped';
    createdAt: string;
    updatedAt: string;
}

interface ScheduledPromptRun {
    id: string;
    taskId: string;
    taskName: string;
    trigger: 'scheduled' | 'manual';
    scheduledAt: string;
    startedAt: string;
    finishedAt?: string;
    status: 'running' | 'success' | 'failed' | 'skipped';
    resultText?: string;
    errorCode?: string;
    errorMessage?: string;
}
```

- プロンプト、タスク、実行履歴、CoWork 履歴はマスコットに依存しないアプリ共通データとする。
- AI 実行時は、その時点のアクティブなマスコットと Chat AI 設定を使用する。
- 実行開始後に設定が変わっても、開始済みの実行には反映しない。
- 実行履歴は直近1,000件または90日分の新しい方を保持し、上限超過分を削除する。
- CoWork 履歴は既存 Chat 履歴と別の名前空間へ保存する。

## 8. アーキテクチャ

### 8.1. 責務

| 層 | 責務 |
| --- | --- |
| Electron メインプロセス | タスク永続化、次回日時計算、発火判定、キュー、多重実行防止、取りこぼし判定。 |
| preload / IPC | タスク CRUD、即時実行、実行状態通知を型付き API として公開する。 |
| Vue 共通層 | Chat / CoWork の切り替え、タスク管理 UI、CoWork 履歴、未読管理。 |
| チャット実行サービス | 既存の共通 `ChatAiService` を使用し、画面の表示状態に依存せず AI を実行する。 |

### 8.2. 実行フロー

1. Electron が期限到達を検出し、実行レコードを `running` で作成する。
2. Electron が共通 `ChatAiService` を、その時点の Chat AI 設定で呼び出す。
3. Electron が結果または正規化済みエラーを実行レコードへ保存する。
4. Electron が次回日時を確定する。
5. 全ウィンドウへ更新イベントを配信し、CoWork が保存済み結果を再読込する。

チャットウィンドウが非表示でも、Electron メインプロセスが起動していれば実行を継続する。

### 8.3. 永続化

- 開発環境はワークスペースの `storage/`、配布環境は Electron の `userData` を使用する。
- 定期実行タスクと実行履歴は、設定ファイルや通常チャット履歴と別ファイルに保存する。
- 一時ファイルへ書き込み後に置換し、直前のバックアップを保持する。
- ファイル破損時はバックアップを読み込み、両方が破損している場合は読み取り専用で起動して UI に通知する。

### 8.4. Web 版

初期リリースの自動スケジュール実行は Electron 版のみ対応する。Web 版では CoWork の閲覧と手動実行を利用できるが、定期実行の保存時に「アプリ起動中のみ実行される」旨を表示する。将来はサーバー側スケジューラへ差し替えられるよう、スケジュール計算とデータ型を Electron 非依存の共有モジュールへ配置する。

## 9. セキュリティとプライバシー

- renderer から受け取るタスク入力を IPC 境界で再検証する。
- IPC 送信前に Vue の Proxy をプレーンオブジェクトへ変換する。
- ID、列挙値、文字数、日時、曜日、間隔の範囲を検証する。
- API キーをタスクまたは実行履歴へ保存しない。
- 通常ログへ API キー、認証ヘッダー、プロンプト全文、AI 応答全文を出力しない。
- CoWork は永続化されるため、シークレットモードの対象外であることを UI に明示する。

## 10. 受け入れ基準

1. ヘッダーのドロップダウンで `Chat` と `CoWork` をキーボード・マウスの両方で切り替えられる。
2. 切り替えても Chat と CoWork の履歴が混ざらず、それぞれの入力内容とスクロール位置が保たれる。
3. 15分間隔、毎時、毎日、毎週のタスクを作成・編集・無効化・再有効化・削除できる。
4. 有効なタスクが期限に達すると1回だけ実行され、成功結果が CoWork に追加される。
5. 失敗時は簡潔なエラーが CoWork に追加され、次回予定が失われない。
6. Chat 表示中に結果が追加されても自動で CoWork へ切り替わらず、未読件数が表示される。
7. 同一タスクの実行中に次回時刻へ達しても、重複した AI 実行が開始されない。
8. アプリ再起動後もタスクと履歴が復元され、7日以内の取りこぼしは最新1回だけ補完される。
9. アプリ終了中は実行されないことが UI と仕様の両方で明示される。
10. 分割、統合、コンパクトの各ウィンドウモードで同じデータと未読状態が表示される。
11. Electron IPC へ送るオブジェクトはプレーンオブジェクト化され、不正な入力はメインプロセスで拒否される。
12. lint、Vue / Electron 型チェック、対象ユニットテストが成功する。
13. CoWork が機能メニューと内容領域に分かれ、`概要` と `スケジュール` を切り替えられる。
14. チャット領域が狭い場合は機能メニューが細いレールへ畳まれ、マウスオーバーまたはキーボードフォーカスで内容の上へ展開できる。

## 11. 未決事項

実装着手前に、次をユーザー確認または UI 試作で確定する。

- CoWork の追加入力が通常 Chat と同じマスコット人格・ツールを使うか、作業向けシステムプロンプトを追加するか。
- 定期結果の OS 通知と TTS を初期リリースに含めるか。
- 実行履歴と CoWork メッセージ本文の保持上限。
- タスクごとに AI エンジン・モデル・マスコットを固定する機能が必要か。
