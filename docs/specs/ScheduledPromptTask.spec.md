# 定期実行タスク・CoWork モード仕様書

> Nitro API サーバーでプロンプトを定期実行し、結果を CoWork に保存する仕様。

## 1. 目的

- ユーザーがプロンプトと実行周期を登録できる。
- Nitro API サーバーの稼働中、登録した周期で AI へプロンプトを送信する。
- 実行結果を通常会話と混在させず、`CoWork` のチャットへ報告する。
- 現在のチャットヘッダーから `Chat` と `CoWork` を切り替えられる。
- 実行成否、次回実行日時、直近の結果をユーザーが確認できる。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 会話種別 | `Chat` または `CoWork`。表示するメッセージ履歴と利用目的を分ける単位。 |
| Chat | ユーザーとマスコットが通常の会話を行う既存の会話種別。 |
| CoWork | 定期実行タスクの登録、実行結果の確認、結果に対する追加会話を行う会話種別。 |
| 定期実行タスク | プロンプト、実行周期、実行状態を持ち、指定時刻に AI 実行を要求するジョブ。 |
| 実行結果 | 定期実行タスクごとの AI 応答、エラー、開始・終了日時を含む記録。 |

## 3. 既存機能との境界

### 3.1. タスク管理ウィジェットとの違い

`docs/specs/widgets/task-management/` のタスクは、ユーザーの予定や TODO を管理・通知する機能である。本機能は AI にプロンプトを実行させる機能であり、データモデルと実行基盤を分離する。

- タスク管理の `Task`、`scheduledAt`、`recurrence` は流用しない。
- 定期実行タスクから通常の TODO を作成する場合は、将来の連携機能として扱う。
- 「予定を知らせるだけ」は既存タスク管理またはタイマー、「調査・要約等を AI に実行させる」は本機能を使用する。

### 3.2. 既存チャットモードとの関係

`Chat / CoWork` は会話種別であり、次の既存状態とは独立する。

- シークレットモード
- ラジオモード
- 画像生成モード
- ウィンドウモード（分割、統合、コンパクト）

初期リリースでは CoWork からラジオモードと画像生成モードを開始できない。シークレットモードは Chat のみに適用し、CoWork の定期実行結果は永続保存する。

## 4. 対象範囲

### 4.1. 初期リリースに含む

- `Chat / CoWork` の切り替え UI。
- CoWork 専用の履歴。
- 定期実行タスクの一覧、作成、編集、有効化、無効化、削除。
- タスクの即時実行。
- 毎時、毎日、毎週、指定間隔の実行周期。
- 実行結果とエラーの CoWork 履歴への投稿。
- 次回実行日時、最終実行日時、最終結果の状態表示。
- サーバー再起動後のタスク復元と停止中の取りこぼし補完。
- 同じサーバーとアカウントを使う Web・Electron・スマホでのタスクと履歴の共有。
- 同一タスクの多重実行防止。

### 4.2. 初期リリースに含まない

- サーバー停止中の実行。
- OS のタスクスケジューラへの登録。
- 外部チャット、メール等への投稿。
- 任意の cron 文字列入力。
- タイムゾーンをまたぐ高度な RFC 5545 対応。
- 失敗時の自動リトライ。
- タスク間の依存関係やワークフロー。

## 5. ユーザー体験

### 5.1. 会話種別の切り替え

現在のチャットヘッダーに表示している「`マスコット名 Chat`」を、ネイティブなドロップダウンリストへ置き換える。

- 選択肢は `Chat` と `CoWork`。
- 初期値は `Chat`。
- 表示例は `マスコット名 / Chat`、`マスコット名 / CoWork` とする。
- 選択変更時にページ遷移や新規ウィンドウを開かず、同じチャット領域の内容を切り替える。
- 選択中の会話種別はウィンドウ間で同期し、アプリ再起動後も復元する。
- キーボードでフォーカス、選択、確定でき、明示的なラベルを持つ。
- ヘッダーのドラッグ操作はドロップダウン上で開始しない。

### 5.2. CoWork のワークスペース

CoWork は定期実行だけに限定せず、今後さまざまな作業機能を追加できるワークスペースとする。

- 広い表示領域では、左に機能メニュー、右に選択した機能の内容を表示する。
- 左メニューの初期項目は `概要` と `スケジュール` とする。
- `概要` には利用できる作業機能への導線と、最近の実行結果を表示する。
- `スケジュール` には定期実行タスクの作成、一覧、状態、実行結果を表示する。
- タスク作成ボタンは左メニューとスケジュール画面のヘッダーから利用できる。
- メニュー項目を増やしても右側の表示領域を共用できる構造とする。
- チャット領域の横幅が狭い場合は左メニューをアイコンだけの細いレールへ畳み、マウスオーバーまたはキーボードフォーカス時に内容の上へオーバーレイ表示する。
- 狭幅判定にはアプリまたは統合ウィンドウ全体ではなく、CoWork が配置されているチャット領域の実幅を使用する。
- DOM とキーボードフォーカスは、メニュー、選択中の内容の順とする。

将来追加する CoWork の追加入力と会話履歴は、選択中の作業機能を妨げない位置へ配置する。タスク作成・編集フォームはスケジュールの内容領域に表示し、閉じると同じ一覧へ戻る。

### 5.3. 定期実行タスクの入力項目

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 名前 | 必須 | 一覧と実行結果に表示する短い名称。1〜100文字。 |
| プロンプト | 必須 | AI へ送信する内容。1〜20,000文字。 |
| 周期種別 | 必須 | `interval`、`hourly`、`daily`、`weekly`。 |
| 間隔 | 条件付き | `interval` は15分以上、他は1以上の整数。 |
| 時刻 | 条件付き | `daily`、`weekly` で指定するローカル時刻。 |
| 曜日 | 条件付き | `weekly` で1つ以上選択する。 |
| 有効 | 必須 | 保存直後からスケジュール対象にするか。既定は有効。 |

フォームは常に可視ラベルを持つ。エラーは対象項目と関連付け、入力後に表示し、保存失敗は `aria-live="polite"` 相当の通知領域でも伝える。

### 5.4. タスク一覧

各タスクに次を表示する。

- 名前。
- 周期の読みやすい要約。
- 有効・無効。
- 次回実行日時。
- 最終実行日時と `成功 / 失敗 / 実行中`。
- `今すぐ実行`、`編集`、`有効化 / 無効化`、`削除`。

削除は確認後に実行する。実行履歴はタスク削除時にも残し、投稿内のタスク名を表示できることとする。

### 5.5. CoWork への投稿

1回の実行につき、完了後に1件の結果メッセージを追加する。

- タスク名。
- 予定実行日時。
- 実際の開始・終了日時。
- 成功時は AI 応答本文。
- 失敗時はユーザー向けの簡潔なエラー。
- 手動実行か定期実行か。

CoWork を表示中のクライアントは初回表示と約10秒ごとに結果を取得する。Chat 表示中も完了した実行 ID を取得し、取得済みの履歴と比較して CoWork 選択肢に未読件数を表示する。未読件数は表示中のアカウントごとに判定し、CoWork を開くとクリアする。非表示中は取得を休止する。

## 6. スケジュール仕様

### 6.1. 時刻とタイムゾーン

- タスクは作成時の IANA タイムゾーンを保持する。初期値は OS の現在タイムゾーン。
- 次回実行日時は ISO 8601 形式で保持する。
- 日次・週次は現地時刻を優先し、夏時間による時刻変更後も指定した壁時計時刻を維持する。
- OS のタイムゾーン変更後は、保存済みタイムゾーンを維持し、自動変更しない。

### 6.2. サーバー稼働中の発火

- Nitro の起動プラグインがリクエストの有無にかかわらず、起動時と約2秒ごとに実行対象を確認する。
- 同じ SQLite DB を使うプロセス間で AI 実行を直列化する。定期実行の確保と次回日時の更新を同じトランザクションでコミットし、所有者・タスク・予定日時に一意制約を設ける。
- 同じタスクが実行中または手動実行待ちの場合、期限に達した予定は `skipped` として記録する。別タスクの予定は空き次第処理する。
- 手動実行を `queued` として永続化する。実行待ちまたは実行中に同じタスクを再度要求した場合は、既存の実行を返す。未開始の手動実行はサーバー再起動後に処理できる。

### 6.3. サーバー停止中の取りこぼし

サーバーの再起動後、保存済みの次回日時から現在までに1回以上の予定があるタスクは、最新の1回だけ補完実行する。

- 過去の全回を連続実行しない。
- 補完実行は通常の定期実行として投稿し、予定実行日時を併記する。
- 無効なタスクは補完しない。
- 7日より古い取りこぼしは実行せず、`skipped` として記録する。

### 6.4. 失敗時

- AI の応答には60秒の制限を設ける。接続・認証・タイムアウトなどの失敗を実行履歴へ記録する。
- 正常終了時は実行をキャンセルする。プロセスが強制終了した場合は、実行開始から90秒経過後に残った `running` を中断として記録する。確保済みの定期実行は再送しない。
- AI 実行の自動リトライは行わない。
- 失敗しても次回予定は通常どおり計算する。
- 外部通信のログは既存の実装ルールに従い、秘密情報とプロンプト全文を平文ログへ出さない。

## 7. データモデル

```ts
type ConversationKind = 'chat' | 'cowork';

type ScheduleRule =
    | { type: 'interval'; intervalMinutes: number }
    | { type: 'hourly'; intervalHours: number; minute: number }
    | { type: 'daily'; intervalDays: number; time: string }
    | { type: 'weekly'; intervalWeeks: number; weekdays: number[]; time: string };

interface ScheduledPromptTask {
    id: string;
    name: string;
    prompt: string;
    schedule: ScheduleRule;
    timeZone: string;
    enabled: boolean;
    nextRunAt: string;
    lastRunAt?: string;
    lastStatus?: 'success' | 'failed' | 'skipped';
    createdAt: string;
    updatedAt: string;
}

interface ScheduledPromptRun {
    id: string;
    taskId: string;
    taskName: string;
    trigger: 'scheduled' | 'manual';
    scheduledAt: string;
    startedAt: string;
    finishedAt?: string;
    status: 'queued' | 'running' | 'success' | 'failed' | 'skipped';
    resultText?: string;
    errorCode?: string;
    errorMessage?: string;
}
```

- プロンプト、タスク、実行履歴、CoWork 履歴はマスコットに依存しないアプリ共通データとする。
- AI 実行時は、サーバーで管理する CoWork 専用モデル設定とシステムプロンプトを使う。
- ユーザーごとに、完了した実行の直近90日以内かつ最新1,000件を保持する。実行待ち・実行中のレコードは完了まで保持する。
- CoWork 履歴は既存 Chat 履歴と別の名前空間へ保存する。

## 8. アーキテクチャ

### 8.1. 共通 API

| メソッドとパス | 操作 |
| --- | --- |
| `GET /api/cowork` | タスクと実行履歴の一覧 |
| `GET /api/cowork/activity` | 未読判定用の完了済み実行 ID |
| `POST /api/cowork/tasks` | タスク登録 |
| `PATCH /api/cowork/tasks/:id` | 内容の更新または有効・無効の切り替え |
| `DELETE /api/cowork/tasks/:id` | タスク削除 |
| `POST /api/cowork/tasks/:id/run` | 手動実行をキューへ登録 |
| `POST /api/cowork/import` | 旧デスクトップ版 JSON の取り込み |

### 8.2. 運用と永続化

- Nitro が `MASCOT_STORAGE_DIR` 配下の `config.db` に CoWork 専用テーブルを作る。標準の保存先はワークスペースの `storage/`。サーバー再起動後も同じデータディレクトリを使う。
- 共有サーバー構成では Web・Electron・スマホを閉じてもサーバー稼働中は実行を継続する。Electron 同梱 Nitro 構成では同梱サーバーの稼働中に実行する。
- 複数端末で共有する場合は同じ Nitro サーバーを利用する。別々の SQLite ファイルに接続したサーバーは独立した環境になる。
- Web とスマホは接続先のサーバーでログインする。Electron は既定でローカルの Nitro に接続する。共有サーバーを使う場合は、Electron を起動する環境に `COWORK_SERVER_ORIGIN=https://サーバー名` を設定する。HTTP はループバックに限る。
- Electron の CoWork から接続先をブラウザーで開き、使用するアカウントでログインする。Web の CoWork スケジュール画面で接続コードを発行し、5分以内に Electron の CoWork に貼り付ける。
- 接続コードは一回限り。Electron が取得するセッションは CoWork の API に限り、最大12時間有効。Electron メインのメモリに保持し、終了時に破棄する。サーバーはコードとセッションのハッシュのみを保存する。

### 8.3. AI 設定

サーバーを起動する環境に設定する。設定は同じサーバーを使う CoWork ユーザー間で共通とする。

| 環境変数 | 値 |
| --- | --- |
| `COWORK_AI_ENGINE` | `gemini`、`openai`、`lmstudio` のいずれか |
| `COWORK_AI_MODEL` | 指定したプロバイダーで利用できるモデル ID |
| `COWORK_AI_API_KEY` | Gemini または OpenAI のサーバー用 API キー |
| `COWORK_LMSTUDIO_ENDPOINT` | Nitro から到達できる LM Studio の URL。既定値は `http://127.0.0.1:1234/v1` |

LM Studio はモデルを読み込んで API サーバーを起動しておく。別ホストを使う場合は、Nitro のホストから到達可能なプライベートネットワークのアドレスを設定する。CoWork は既存の `ChatAiService` のテキスト生成をツール無効で呼び出す。

### 8.4. 旧デスクトップ版からの切り替え

1. 旧版を動かしている端末で Electron を終了する。旧 JSON を最終状態でコピーする。
2. 旧版の `scheduled-prompt-tasks.json` を確認する。開発時は旧ワークスペースの `storage/`、配布版は Electron の `userData` 直下にある。
3. 移行先のサーバーに対象アカウントでログインし、CoWork のスケジュール画面で「旧デスクトップ版のデータを取り込む」から JSON を選ぶ。
4. タスクと結果が表示されることを確認する。旧デスクトップ版で保存していたコピーはバックアップとして保管する。

同じアカウントへの再取込は既存の ID を再登録しない。削除済みの取り込み項目も復活させない。取込時点までに過ぎた予定は再生せず、履歴上の未完了実行は中断に変換する。新しい Electron 版の起動経路から旧スケジューラは外す。切り替え後は旧版を並行起動しない。

## 9. セキュリティとプライバシー

- Nitro の認証コンテキストにある内部ユーザー ID を所有者とし、API 入力で所有者を指定させない。
- `ALLOW_AUTH_BYPASS=true` は専用のテスト環境に限る。認証バイパス時のリクエストは同じテストアカウント扱いになる。
- ID、列挙値、文字数、日時、曜日、間隔の範囲を検証する。
- API キーをタスクまたは実行履歴へ保存しない。
- 通常ログへ API キー、認証ヘッダー、プロンプト全文、AI 応答全文を出力しない。
- CoWork は永続化されるため、シークレットモードの対象外であることを UI に明示する。

## 10. 受け入れ基準

1. ヘッダーのドロップダウンで `Chat` と `CoWork` をキーボード・マウスの両方で切り替えられる。
2. 切り替えても Chat と CoWork の履歴が混ざらず、それぞれの入力内容とスクロール位置が保たれる。
3. 15分間隔、毎時、毎日、毎週のタスクを作成・編集・無効化・再有効化・削除できる。
4. 有効なタスクが期限に達すると1回だけ実行され、成功結果が CoWork に追加される。
5. 失敗時は簡潔なエラーが CoWork に追加され、次回予定が失われない。
6. Chat 表示中に結果が追加されても自動で CoWork へ切り替わらず、未読件数が表示される。
7. 同一タスクの実行中に次回時刻へ達しても、重複した AI 実行が開始されない。
8. サーバー再起動後もタスクと履歴が復元され、7日以内の取りこぼしは最新1回だけ補完される。
9. すべてのクライアントを閉じても、共有サーバーの稼働中にタスクが実行される。
10. 同じアカウントで接続する Web・Electron・スマホから同じタスクと履歴を参照できる。
11. 別ユーザーのタスク・履歴の取得や変更、不正な JSON 入力を API が拒否する。
12. lint、Vue / Electron 型チェック、対象ユニットテストが成功する。
13. CoWork が機能メニューと内容領域に分かれ、`概要` と `スケジュール` を切り替えられる。
14. チャット領域が狭い場合は機能メニューが細いレールへ畳まれ、マウスオーバーまたはキーボードフォーカスで内容の上へ展開できる。

## 11. 未決事項

実装着手前に、次をユーザー確認または UI 試作で確定する。

- CoWork の追加入力が通常 Chat と同じマスコット人格・ツールを使うか、作業向けシステムプロンプトを追加するか。
- 定期結果の OS 通知と TTS を初期リリースに含めるか。
- タスクごとに AI エンジン・モデル・マスコットを固定する機能が必要か。
