# Mastra 統合仕様

## 1. 目的

MastraをAIエージェントのオーケストレーション基盤として段階導入し、既存のチャット、WebSocket、TTS、ツール、スケジュールプロンプトを維持しながらAgent、Memory、Workflow、Observabilityを評価できる構成にする。

## 2. 適用範囲

フェーズ1・2とフェーズ3の既存ツール・LM Studio接続移行では次を対象とする。

- `@mastra/core`によるMastraランタイムとAgentの生成
- Nitroサーバープロセス内での遅延初期化
- Request Contextによるリクエスト単位のモデル選択
- Gemini/OpenAI/LM Studioの対話チャットをMastraへ統一
- 既存履歴、テキスト・画像添付、システムプロンプトのAgent入力への変換
- 既存WebSocketのチャット応答、TTS、感情タグ、タイマーイベントとの接続
- 設定で有効な場合だけ公開する天気・Web検索・概算位置・音量・アプリ起動ツール
- 認証済みユーザーのタスク・メモ操作と既存画面更新イベント
- LM StudioのOpenAI互換Chat Completions接続と既存の生成パラメーター
- NitroビルドとElectron内蔵Node.jsでの実行互換性確認

次は後続フェーズとする。

- ブラウザのページ操作ツール（既存チャットには未実装）
- Mastra Memoryの観察型記憶・意味検索と配布物の検証
- Workflow、Studio、MCP、外部Observability
- 要約・読み辞書など、対話以外で使う旧生成サービスの移行

## 3. 実行アーキテクチャ

- MastraランタイムはNitroサーバープロセスだけに配置する。
- ElectronメインプロセスにはMastraを生成しない。
- 独立したMastraサーバーや追加の待受ポートを作成しない。
- Mastra関連コードは`app/src/server/mastra/`以下へ配置する。
- MastraインスタンスとAgentは、最初に必要になった時点で一度だけ生成する。
- Nitro の CoWork プラグインが Mastra background workers を起動し、終了時は CoWork Agent の実行を中断してから workers を停止する。
- Mastra の永続ストレージは`MASCOT_STORAGE_DIR/mastra/runtime.db`を使う。CoWork のタスクと実行履歴は既存の`config.db`に保持する。
- Nitroの`/api/ping`はMastra機能の有効状態と初期化状態を返す。

## 4. チャット経路

- Gemini/OpenAI/LM Studioの対話チャットはMastraのみを使う。未対応エンジンはエラーとし、旧経路へ切り替えない。従来の環境変数`MASTRA_CHAT_ENABLED`は参照しない。
- 互換用のLM StudioチャットHTTP APIもMastraを使い、従来の応答形式を維持する。他のAI処理は既存経路を使う。
- CoWork の定期実行と手動実行は Mastra scheduler と専用の threadless `cowork-agent` を使う。schedule lifecycle hook が CoWork DB のキュー・履歴と連携する。運用設定は [CoWork 仕様](ScheduledPromptTask.spec.md) を参照。
- `toolsWeather`、`toolsWebSearch`、`toolsGpsLocation`、`toolsVolume`、`toolsAppLauncher`が明示的に`true`の発話だけ対応ツールを公開する。無効・未指定の場合は公開しない。
- タスク・メモは認証済みWebSocket接続のユーザー別DB操作関数が利用できる場合だけ公開する。
- 発話のツール設定が無効なら、エンジンや認証状態にかかわらずタスク・メモを含めすべてのツールを公開しない。
- LM Studioのチャットテンプレートエラーを検出した場合、応答本文を表示せず設定画面への案内を返す。ツールを外した自動再試行はしない。
- ブラウザのページ操作など未対応の操作は実行済みを装わず、利用不可を伝える。
- Mastra経路で処理を始めた後、失敗時に既存経路へ自動再送しない。

## 5. Agentとモデル

- `@mastra/core`は1.83.0、`@mastra/memory`は1.41.1、`@mastra/libsql`は1.30.0、`@lmstudio/sdk`は2.1.0、AI SDKは7系を使用する。
- Agent IDは通常会話の`mascot-agent`と、定期実行専用の`cowork-agent`とする。
- CoWork Agentは会話用ツールとMemoryを持たない。タスク所有者の CoWork 設定を優先してモデルを選び、各実行でその所有者のメイン設定に登録されたキーを優先して使用する。結果は CoWork の実行履歴に保存する。
- 天気、Web検索、概算位置、音量、アプリ起動、タスク、メモのツールをリクエスト設定に応じてAgentへ動的に登録する。Workflowは登録しない。
- 現行処理と同じく、最初は全文を返す`agent.generate()`を使用する。
- 通常会話の`mascot-agent`のモデルは固定せず、実行ごとのRequest Contextから解決する。
- APIキー、認証トークン、LM Studioの資格情報をRequest Contextへ直接格納しない。
- APIキーを使って生成したモデルオブジェクトをリクエスト単位で渡し、認証情報を持つモデルをリクエスト間でキャッシュしない。
- OpenAIはResponses APIを使用する。制限付きキーには`api.responses.write`権限が必要である。
- LM Studioは設定されたエンドポイントの`/v1/chat/completions`を使用し、APIキーを要求しない。モデルと接続先はリクエストごとに解決する。
- LM Studioの`repetitionPenalty`と`enableThinking: false`は既存経路と同じリクエスト本文へ変換する。
- LM Studioの対話経路では`/no_think`を追加しない。送信する過去履歴からは同トークンを除去し、保存済み履歴は変更しない。SDKの思考設定をMastra経由で利用する経路は未実装である。
- Request Contextへ格納できる識別情報はエンジン名とモデルIDに限定する。
- システムプロンプトはRequest Contextへ格納せず、Agent実行オプションとして渡す。
- 通常チャットでは、Mastra Memory（`@mastra/memory`）とlibSQLが会話履歴の正本となる。WebSocket側で成功した発話・表示用の応答と添付を保存し、次回の生成では同一会話の増分要約と予算に収まる直近原文を使う。システムプロンプト、ツール呼び出しの生データ、失敗時の応答は保存しない。
- 画面の履歴取得・削除には認証付きの`/api/mastra-history`を使用する。ユーザーとマスコットから保存範囲を導出し、会話IDで会話を分離する。削除は保存先の処理が成功した場合にのみ画面へ反映する。生成中の同一会話の削除は拒否する。
- シークレット会話と自発発話は Mastra Memory に保存しない。シークレット会話は画面を開いている間だけ保持する。旧履歴は元の場所に保持し、Mastra Memory へ自動取り込みしない。詳細は [旧会話履歴の取り扱い](server_db_specs.md#3-旧会話履歴の取り扱い) を参照。
- 画像はBase64データをリクエストへ直接含めるため、OpenAI Files APIへの事前アップロードを行わない。
- 生成時間の上限は承認待ちを除いて60秒とする。承認は接続ごとに順番に表示し、各画面の表示開始からサーバー側45秒、画面側40秒で拒否する。承認待ち中もWebSocket切断は即座に反映し、中断後は変更・正常応答の保存を行わない。
- 履歴取得に失敗した場合は画面内で再試行できる。取得が成功するまでは送信しない。応答は送信元の会話へ反映し、表示中のマスコットやモードが変わっても取り違えない。
- 選択中の通常会話IDだけを接続先・利用者・マスコットごとにローカルへ保存する。本文はMastra Memoryだけに保存し、シークレット会話の選択は永続化しない。タイトルは先頭15文字と省略記号で統一する。
- 会話選択の利用者識別子は認証済み履歴APIが返す不透明な`selectionScope`を使い、設定画面側の認証ストアの読み込み時期に依存しない。履歴取得失敗時は再試行、読み込み済みの履歴の削除失敗時はエラーを閉じる操作を表示する。
- Agentは全文を返し、既存WebSocketの応答・TTS処理へ渡す。ストリーミングは別途評価する。
- 天気取得は既存LM Studio経路とMastra経路で共通処理を利用し、Mastraでは1発話につき天気ツールを最大1回だけ実行する。
- Web検索は既存LM Studio経路とMastra経路で共通処理を利用し、DuckDuckGo軽量版から最大3件取得する。Mastraでは1発話につき最大1回だけ実行する。検索結果の本文は第三者のデータと扱い、そこに含まれる命令へ従わない。
- IPアドレス由来の位置情報は概算として扱い、取得に失敗したときに東京の座標を現在地として返さない。
- タスク・メモは既存のユーザー別DB処理へ委譲し、成功後は既存の`task-action`・`memo-action`イベントで画面を同期する。同一発話で同じ変更を重複実行しない。
- 同一発話内の同じ変更は引数のキー順に依存せず一度だけ試行する。Mastra経路ではユーザー・発話ID・ツール名・正規化した入力のハッシュを操作前に永続記録し、再送や再起動後も同じ操作を再実行しない。保存失敗や結果不明でも安全側に倒し、実行せず確認を促す。別発話や異なる引数の操作は同一とみなさない。試行記録は利用者データ領域に保持し、自動削除しない。
- Mastraのツール実行開始・成功・失敗は`tool-status`で通知し、チャットの応答待ち表示に反映する。通知にはツール名と状態のみを含め、入力や結果は含めない。
- ツールログは通常、ツール名・成否を出し、タスク・メモは操作種別と検索件数、Web検索は結果件数を表示する。検索語・結果本文は通常ログに出力しない。`MASTRA_TOOL_DEBUG_CONTENT=true`を起動環境で指定した場合のみツール入力・結果を最大4000文字ずつ出力する。APIキー等を示すキー名はマスクするが、本文中の認証情報や個人情報の完全な除去は保証しない。
- Mastra経路のタスク・メモの追加・更新・削除、音量調整、アプリ起動は、各操作の内容を日本語の確認画面で示して個別に承認を求める。検索は確認しない。利用者は対象ツール全体の確認を省略でき、ツール設定から再開できる。省略時も操作記録による重複防止を適用する。拒否、時間切れ、接続切断、操作ID欠落または記録失敗時は実行しない。承認応答は要求した接続だけで受け付ける。Legacy経路は対象外である。
- Mastraの`launchApp`は電卓とメモ帳のみを許可し、モデル入力をOSコマンドとして実行しない。
- 固定座標のない日本国内の都市名はOpen-Meteoの地名検索で解決する。日本語の省略形で見つからない場合は`市`、`町`、`村`の接尾辞を試す。
- 地名検索で候補を特定できない場合は東京の天気として返さず、取得できない旨を明示する。

## 5.1 プロンプトと会話圧縮

- GUI とマスコット連携 CLI は WebSocket の `chat-send` に `promptVersion: 1` と `chatMode` を設定する。モードは `normal`、`secret`、`radio`、`secret_radio`、`active_talk`、`secret_active_talk`、`cli_override`、`secret_cli_override`。通常・通常ラジオ・通常 CLI 上書きは、認証と所有権および保存識別子がそろったときに保存する。
- 新形式では所有マスコットの `config.yaml` と `mascot_config.json`、個別 Markdown から基礎指示を作る。未同期プロフィールはローカルの値を使う。旧形式と CLI の明示上書きでは、送信済みの指示を尊重する。
- ラジオ指示はサーバー上の radio プロンプトと同梱の既定文を参照する。拡張ラジオは LM Studio の設定時に使う。Irodori の音声タグ指示は Irodori かつ TTS が有効なときに追加する。
- 正常応答の保存と同じ DB 更新で単調増加する保存順を割り当てる。メッセージ ID、表示順、添付、タグ整形、再送処理を維持する。既存の Mastra 原文には初回に日時・ID 順で保存順を割り当てる。
- 前回の要約と次の確定原文範囲を、選択済みのチャットモデルと接続先で要約する。会話の世代と対象範囲が一致したときだけ確定する。削除・原文変更は DB 更新時に派生要約を無効化する。圧縮に失敗した場合も、現在の入力・指示・添付と出力枠を差し引いた予算で対話を継続する。履歴予算はローカルとクラウドで保守的に見積もる。

## 5.2 伴走記憶と横断検索

- 新形式の通常会話と通常ラジオの返信から、出所を確認できる本人のテキストだけを抽出する。外部ツール実行時の発言、出所不明の旧履歴、AI 応答、シークレット、自発発話、CoWork は抽出対象外とする。
- 保存からクラウドは10分、LM Studio は20分の無操作を目安に、同一会話の対象発言を入力上限内でまとめて1回の抽出と1つの更新履歴にする。抽出は直近の対象会話でサーバーが受理したモデル設定を使い、認証情報は `user_config.json` から取得する。同じ設定を利用できない場合は `pending_credentials` として保留する。LM Studio の接続先の設定がなければ、`127.0.0.1:1234/v1` と `localhost:1234/v1` の既定の HTTP 接続先を許可する。既定以外は正規化後の設定値と一致する場合に限る。認証以外の実行・解析失敗は3回までとする。Electron 終了時は実行を中断し、期限付きで終了を待つ。
- 自動更新は既定で有効。マスコット別の `user.md`、`memory.md`、`pulse.json` を同じ排他と更新記録で扱う。抽出した項目に根拠となった発言を紐づける。元発言が消えた項目と、それを含むバッチの Undo 履歴は無効にする。差分 Undo は対象更新だけを戻し、同じ箇所が編集済みなら競合を返す。Markdown の管理ブロックを手動削除したときは、対応する記憶の管理情報と差分を同時に整理する。
- 気がかりは有効なものを最大5件扱う。通常会話と通常ラジオは新規セッションまたは前回発言から6時間以上経過したとき、自発発話は発話時に声かけの候補を選ぶ。声かけには有効期限、24時間のクールダウン、最大3回を適用する。候補は生成中に予約し、正常応答のときだけ回数と時刻を確定する。近況と利用者共有タスクの概要は直近の入力側に添える。
- 認証済みの所有マスコットでツールが有効な保存会話に、読み取り専用の `searchPastRecords` を公開する。会話は同じ利用者・マスコットの別セッションに限定し、候補を返す前に原文と所属を照合する。メモとタスクは利用者共有の正本を検索し、出典種別を返す。
- 3文字以上は FTS5 `trigram`、1〜2文字は正規化部分一致を使う。自然文からは検索語を抽出する。既存履歴は検索時に順次索引化し、検索失敗時も通常応答を継続する。

## 6. ログとトレース

- 初期段階では外部Observabilityエクスポーターを設定しない。
- Request Contextのスパン情報へAPIキー、認証トークン、システムプロンプト、ユーザーメッセージを含めない。
- ログへ出力できるのはMastraの有効状態、初期化状態、エンジン名、モデルID、処理結果、所要時間である。
- モデルオブジェクト全体やリクエスト本文をログへ出力しない。
- Mastra経路のエラー時はAPI応答本文と例外メッセージをクライアントへ転送せず、固定の日本語エラー文を返す。

## 7. ヘルスチェック

`GET /api/ping`は従来の応答に次を追加する。

```json
{
    "mastra": {
        "enabled": true,
        "initialized": false
    }
}
```

- `enabled`は互換性のため残し、常に`true`を返す。
- `initialized`は現在のNitroプロセス内でMastraインスタンスが生成済みかを表す。
- ヘルスチェックはMastraを初期化しない。
- APIキー、モデル設定、エラー詳細を返さない。

## 8. ビルドと配布

- 最初にNitroの既定バンドル設定でビルドする。
- `@mastra/core`を外部化するのは、既定バンドルでビルドまたは実行上の問題が確認された場合だけとする。
- 外部化する場合、Electron配布物に実行時依存が含まれることを確認する。
- RendererバンドルへMastraサーバーコードを含めない。
- Electron内蔵Node.jsで`.output/server/index.mjs`と`/api/ping`を起動確認する。

## 9. テスト要件

- 廃止した環境変数を指定してもMastra経路を使うことを検証する。
- Mastraランタイムが遅延初期化され、同一プロセス内で再利用されることを検証する。
- 異なるモデルを連続指定した場合に、各リクエストが指定モデルを使用することを検証する。
- Request Contextのスパン表現にモデル内部のAPIキーが含まれないことを検証する。
- GeminiとOpenAIの実接続テストは`npm run test:mastra:live`からだけ実行し、通常のVitestではスキップする。
- 実接続テストは`GEMINI_API_KEY`と`OPENAI_API_KEY`をテストプロセスから参照し、値をログ、エラー、スナップショットへ出力しない。
- Mastraテストには`.env`を探索しない専用Vitest設定を用い、環境変数は起動元からだけ受け取る。
- WebSocket経路切替、履歴・添付、既存チャット・音声イベント、切断時キャンセル、エラー文のマスキングを検証する。
- 天気ツールの設定別公開、入力検証、外部通信の重複防止、ツール結果を使ったAgentの最終応答を検証する。
- 移植した各ツールの設定別公開、Web検索結果の受け渡し、タスク・メモのユーザー分離と画面同期、任意コマンド入力の拒否を検証する。
- 実接続の既定モデルはGeminiを`gemini-3.5-flash-lite`、OpenAIを`gpt-4o-mini`とし、`MASTRA_TEST_GEMINI_MODEL`と`MASTRA_TEST_OPENAI_MODEL`で上書きできる。
- lint、型チェック、対象Vitest、本番ビルドを実行する。

## 10. ロールバック

- 環境変数での切り戻しは廃止する。切り戻しが必要な場合は前のリリースを使用する。Mastra MemoryのDBは削除しない。
- CoWorkの定期実行、要約、読み辞書などが利用する`ChatAiService`は残す。
