# CLI 仕様

Codex などからサーバーの動作を確認するため、Node.js で実行する CLI を `app/cli/` に配置する。CLI は既存の Nitro サーバーに接続し、Mastra を別途起動しない。

## ping

`app/` で `node cli/index.js ping --url http://127.0.0.1:3000 --timeout 5000` を実行する。両オプションは省略可能で、それぞれ例の値が既定となる。URL は HTTP または HTTPS のオリジンのみを受け付け、ユーザー情報、パス、クエリ、フラグメントやリダイレクトは受け付けない。タイムアウトはミリ秒単位の正の整数である。

成功時は標準出力へ `version: 1`、`ok: true`、`result` を含む JSON を一行出力する。結果には pong、時刻、Mastra の状態を含む。失敗時は `ok: false` とエラー種別・メッセージを返す。終了コードは成功 0、入力不正 2、接続失敗 4、タイムアウト 5、サーバーまたは応答の異常 6 とする。API キーや認証情報を引数に取らない。

## chat send

`node cli/index.js -p --url http://127.0.0.1:3000 --timeout 90000` の標準入力に JSON を渡す。`--print` と `chat send` も同じ動作となる。既定のタイムアウトは 90 秒。WebSocket は既存の `/ws` に接続し、一接続で一発話のみ行う。Node.js と `app/` の依存関係が必要である。

入力例: `{"message":"こんにちは","engine":"lmstudio","model":"モデル名","lmstudioEndpoint":"http://127.0.0.1:1234"}`。エンジンは `lmstudio`、`openai`、`gemini` に限る。システムプロンプトやモデル設定などは入力で明示し、GUI の設定やプロンプトを自動取得しない。API キーは環境変数 `TONARICE_AI_API_KEY`、既存の Google ID トークンは `TONARICE_SESSION_TOKEN` から渡す。トークンは Cookie として送信する。いずれかの資格情報を指定した場合、接続先は HTTPS またはローカルに限定する。認証を必要としない ping は従来どおり動作する。

既定では TTS と全ツールを無効にし、履歴を保存しない。`enableTools: true` でツールを有効にできる。承認要求は既定で拒否し、`approval: {"name":"ツール名","input":{...}}` を指定した場合のみ、名前と入力が完全一致する操作を一回承認する。その他は拒否する。結果には対話応答、感情、発話 ID、各承認の成否を含む。ツールによる処理の成否は承認の成否とは別であり、応答や対象データで確認する。

通常会話として保存するには `activeMascotId`、`memorySessionId`、`memoryUserMessageId`、それより大きい `memoryAssistantMessageId` を明示する。ID は正の安全な整数で既存メッセージと衝突しないものを利用者が指定する。サーバーの Mastra Memory が履歴を管理する。指定しない場合は一時会話となり、必要な過去履歴は `history` で渡す。履歴の一覧・削除コマンドは未実装である。

認証失敗の終了コードは 3。タイムアウトや送信後の切断は自動再送せず、処理結果が不明である旨を返す。標準出力は JSON 一行とし、会話応答以外の内部エラーやサーバーの例外本文を公開しない。Ctrl+C ではプロセスを終了し、WebSocket 接続を閉じる。実データを変更する操作は、隔離されたデータ領域で検証する。

## chat interactive

`app/` で `node cli/index.js` を実行すると、1 行ずつ入力してマスコットと続けて会話できる。`chat interactive` を明示してもよい。`--engine` は `lmstudio`（既定）、`openai`、`gemini` を指定できる。必要に応じて `--model`、`--lmstudio-endpoint`、`--system-prompt`、`--url`、`--timeout` を指定する。URL・タイムアウト・認証情報は `chat send` と同じ規則を使う。GUI の設定やプロンプトは自動取得しない。

会話中は `/help` でコマンドを表示し、`/clear` で文脈を消去し、`/exit` または `/quit`、EOF で終了する。Ctrl+C は実行中の通信を切断して終了コード 130 を返す。通信エラー時はメッセージを表示して入力に戻り、失敗した発話は履歴に追加しない。再送は自動で行わない。

`/login` は既存サーバーの Google ログインをブラウザーで開く。自動起動できない場合は表示された URL を手動で開く。ログイン要求は 5 分間有効で、ランダムな検証値を使って認証結果を一度だけ CLI に渡す。認証情報は CLI の実行中のみメモリに保持し、標準出力やファイルへ保存しない。ログイン後は認証情報を対話とマスコット操作に使用し、アカウント間の混在を防ぐため会話文脈とマスコット選択を初期化する。中断は Ctrl+C で行う。接続先は HTTPS またはローカルに限る。サーバーの Google OAuth 設定と、Google 側に登録済みのコールバック URI が必要である。

`/mascot` は一覧を表示し、番号で選択、`c` で作成、`p` で選択中のマスコットの性格を設定する。`/model` は選択中のマスコットの現在の対話エンジンとモデルを表示し、エンジンの番号とモデル ID を入力して変更する。設定中は `/cancel` で中止できる。最初の選択では GUI のアクティブ ID を参照し、見つからなければ一覧の先頭を使う。切り替えと性格変更時は対話の文脈を消去する。マスコットの選択自体は CLI 内のみに適用する。

マスコットの作成と設定には、認証済みの既存サーバー API を使う。プロフィールとチャット設定は各マスコットの `config.yaml` に保存し、従来の `mascot_config.json` と互換性を保つ。古いデータに YAML がなければ JSON を読み取る。CLI では選択したマスコット固有のプロフィールとモデルを発話に使う。GUI は従来どおりグローバルのエンジン・モデル設定を優先する場合がある。モデル ID は手入力し、外部サービスのモデル一覧取得は行わない。

直近 10 メッセージをプロセス内に保持して次の発話に渡し、終了時に破棄する。サーバーの Memory には保存せず、GUI の会話とも共有しない。音声とツールは無効である。対話モードは人が読む形式を出力し、機械向け JSON は従来の `chat send` を使う。
