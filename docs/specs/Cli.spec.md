# CLI 仕様

Codex などからサーバーの動作を確認するため、Node.js で実行する CLI を `app/cli/` に配置する。CLI は既存の Nitro サーバーに接続し、Mastra を別途起動しない。

`app/` で `npm run cli` を使って起動すると、Node.js の `--env-file=.env.local` により `app/.env.local` を読み込む。Node.js 20.6 以降と同ファイルが必要。既に設定済みの環境変数はファイルより優先される。`node cli/index.js` で直接起動する場合は自動読込されないため、必要に応じて `node --env-file=.env.local cli/index.js` を指定する。

接続先の開発サーバーが未起動なら `app/` の別ターミナルで `npm run dev:cli` を実行する。このコマンドも `.env.local` をサーバープロセスへ読み込む。別 workspace の GUI と同じ保存データを使うには、サーバー起動前に `MASCOT_STORAGE_DIR` へその GUI の保存ディレクトリを明示する。

ポートと接続先は環境変数で切り替えられる。サーバー起動時は `--port` 未指定の場合に `TONARICE_PORT`、次に `PORT`（1〜65535 の整数）を使用する。CLI 側は `--url` 未指定の場合に `TONARICE_CLI_URL`、次に `TONARICE_PORT`、次に `PORT` から `http://localhost:<ポート番号>` を組み立て、いずれも未指定なら `http://localhost:3000` を使う。

動作テストなど実データを変更したくない場合は、`npm run dev:cli:isolated` または `npm run dev:cli -- --isolated-storage`（任意で保存先パス指定可: `--isolated-storage <dir>`）を使う。`--isolated-storage` を指定すると `.env.local` の `MASCOT_STORAGE_DIR` を上書きして隔離ディレクトリで起動し、パス省略時に自動生成した一時ディレクトリはサーバー終了時に自動削除される。また、隔離起動時は通常開発サーバーの PID 追跡ファイルを上書きしない。

## ping

`app/` で `node cli/index.js ping --url http://localhost:3000 --timeout 5000` を実行する。両オプションは省略可能で、タイムアウトの既定は 5000 ミリ秒、接続先の既定は上記環境変数規則に従う。URL は HTTP または HTTPS のオリジンのみを受け付け、ユーザー情報、パス、クエリ、フラグメントやリダイレクトは受け付けない。タイムアウトはミリ秒単位の正の整数である。

成功時は標準出力へ `version: 1`、`ok: true`、`result` を含む JSON を一行出力する。結果には pong、時刻、Mastra の状態を含む。失敗時は `ok: false` とエラー種別・メッセージを返す。終了コードは成功 0、入力不正 2、接続失敗 4、タイムアウト 5、サーバーまたは応答の異常 6 とする。API キーや認証情報を引数に取らない。

## chat send

`node cli/index.js -p --url http://127.0.0.1:3000 --timeout 90000` の標準入力に JSON を渡す。`--print` と `chat send` も同じ動作となる。既定のタイムアウトは 90 秒。WebSocket は既存の `/ws` に接続し、一接続で一発話のみ行う。Node.js と `app/` の依存関係が必要である。

入力例: `{"message":"こんにちは","engine":"lmstudio","model":"モデル名","lmstudioEndpoint":"http://127.0.0.1:1234"}`。エンジンは `lmstudio`、`openai`、`gemini` に限る。システムプロンプトやモデル設定などは入力で明示し、GUI の設定やプロンプトを自動取得しない。API キーは `TONARICE_AI_API_KEY` を最優先し、未指定時は OpenAI では `OPENAI_API_KEY`、Gemini では `GEMINI_API_KEY` を使う。既存の Google ID トークンは `TONARICE_SESSION_TOKEN` から Cookie として送信する。いずれかの資格情報を指定した場合、接続先は HTTPS またはローカルに限定する。認証を必要としない ping は従来どおり動作する。

既定では TTS と全ツールを無効にし、履歴を保存しない。`enableTools: true` でツールを有効にできる。承認要求は既定で拒否し、`approval: {"name":"ツール名","input":{...}}` を指定した場合のみ、名前と入力が完全一致する操作を一回承認する。その他は拒否する。結果には対話応答、感情、発話 ID、各承認の成否を含む。ツールによる処理の成否は承認の成否とは別であり、応答や対象データで確認する。

通常会話として保存するには `activeMascotId`、`memorySessionId`、`memoryUserMessageId`、それより大きい `memoryAssistantMessageId` を明示する。ID は正の安全な整数で既存メッセージと衝突しないものを利用者が指定する。サーバーの Mastra Memory が履歴を管理する。指定しない場合は一時会話となり、必要な過去履歴は `history` で渡す。履歴の一覧・削除コマンドは未実装である。

認証失敗の終了コードは 3。タイムアウトや送信後の切断は自動再送せず、処理結果が不明である旨を返す。標準出力は JSON 一行とし、会話応答以外の内部エラーやサーバーの例外本文を公開しない。Ctrl+C ではプロセスを終了し、WebSocket 接続を閉じる。実データを変更する操作は、隔離されたデータ領域で検証する。

## chat interactive

`app/` で `npm run cli` を実行すると、1 行ずつ入力してマスコットと続けて会話できる。`--engine` に `lmstudio`、`openai`、`gemini` を指定できる。必要に応じて `--model`、`--lmstudio-endpoint`、`--system-prompt`、`--url`、`--timeout` を指定する。npm 経由では `npm run cli -- --engine lmstudio` のように引数を渡す。URL・タイムアウト・認証情報は `chat send` と同じ規則を使う。

会話中は `/help` でコマンドを表示し、`/clear` で新しい会話を開始し、`/exit` または `/quit`、EOF で終了する。端末では Esc で選択中のメニューを取り消せる。応答待ち中の Esc は通信を中断して入力に戻り、送信後の処理結果は不明と表示する。Ctrl+C は CLI を終了コード 130 で終了する。通信エラー時はメッセージを表示して入力に戻り、失敗した発話は履歴に追加しない。再送は自動で行わない。

`/login` は既存サーバーの Google ログインをブラウザーで開く。自動起動できない場合は表示された URL を手動で開く。ログイン要求は 5 分間有効で、ランダムな検証値を使って認証結果を一度だけ CLI に渡す。認証情報は CLI の実行中のみメモリに保持し、標準出力やファイルへ保存しない。ログイン後は認証情報を対話とマスコット操作に使用し、アカウント間の混在を防ぐため会話文脈とマスコット選択を初期化する。ログイン待ちは Esc で中断できる。接続先は HTTPS またはローカルに限る。サーバーの Google OAuth 設定と、Google 側に登録済みのコールバック URI が必要である。

`/mascot` は一覧を表示し、番号で選択、`c` で作成、`p` で選択中のマスコットの性格を設定する。各操作は入力後 Enter で決定する。性格設定では現在のプロフィールを表示し、新しい内容を複数行で入力して `/save` で保存する。空にする場合は `/empty`、変更を破棄する場合は `/cancel` または Esc を使う。保存に失敗した場合は入力内容を保持し、再度 `/save` を実行できる。`/model` は選択中のマスコットの現在の対話エンジンとモデルを表示し、エンジンの番号とモデル ID を入力して変更する。設定中は `/cancel` で中止できる。最初の送信前に GUI のアクティブ ID を参照し、見つからなければ一覧の先頭を使う。マスコットの選択自体は CLI 内のみに適用する。

マスコットの作成と設定には、既存サーバー API を使う。`ALLOW_AUTH_BYPASS=true` のサーバーでは GUI と同じローカル開発ユーザーを使用し、ログインは不要である。プロフィールとチャット設定は各マスコットの `config.yaml` に保存し、従来の `mascot_config.json` と互換性を保つ。古いデータに YAML がなければ JSON を読み取る。

通常の対話では GUI と同様にグローバルのエンジン・モデルをマスコット固有設定より優先し、API キー、LM Studio 接続先、生成パラメーターも取得する。環境変数の API キーと起動オプションは GUI 設定より優先する。CLI 内で `/model` を変更した場合は選択中にその設定を優先する。マスコットのプロフィールと Electron が参照するワークスペース内のプロンプトファイルを読み込む。モデル ID は手入力し、外部サービスのモデル一覧取得は行わない。

GUI と同じ Mastra Memory を利用し、最初は選択中マスコットの最新の通常会話を使用する。GUI が現在選択している会話 ID はブラウザー内にあるため、自動共有されない。`/history` で保存済み会話を表示・選択でき、`/clear` は履歴を削除せず新しい会話を開始する。生成成功時の発話はサーバーに保存され、GUI 側でも履歴を再読み込みすれば参照できる。シークレット会話とブラウザーのローカルストレージだけにあるプロンプトは共有しない。音声とツールは無効である。対話モードは人が読む形式を出力し、機械向け JSON は従来の `chat send` を使う。

`/private` はプライベート会話と通常会話を切り替える。プライベート会話では保存済みの通常履歴を読み込まず、会話は CLI のメモリ内にのみ保持し、切り替えや終了で破棄する。`/clear` はそのプライベート会話の文脈を消去し、`/history` は通常会話へ戻るよう案内する。モデルにメッセージを送るため、利用する AI サービスには内容が送信される。

`/memo` と `/todo` は現在のユーザーのメモ・タスクを一覧表示する。`/memo help` と `/todo help` は操作一覧を表示する。共通操作は `add 内容`、`edit ID 内容`、`delete ID` で、タスクは `done ID` と `reopen ID` にも対応する。ID は一覧で確認する。これらはプライベート会話中でも通常のメモ・タスクを変更し、履歴の非保存とは別に永続化される。接続中の同一ユーザーの GUI へ既存の同期イベントを通知する。
